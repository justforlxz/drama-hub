# ADR-0001：合并集用虚拟 HLS 分片聚合，不物化

状态：已接受（2026-10-27）。**部分被取代**（2026-10-30，ADR-0007）：「单集（不合并）不走这条路，仍是 MP4 字节透传」不再成立——单集也走自造 HLS，对外统一为 `/video/{id}.m3u8`。虚拟 HLS 聚合本身、以及「不物化、不字节拼接」的结论不变。

## 背景

需求要「10 集合成 1 集，Emby 里显示为一条剧集」。源是红果官网的**渐进式 MP4**（一集一个完整文件，`ftyp+moov+mdat`，
`moov` 只描述本集），不是可拼接的 fMP4 分片序列。

候选方案：

1. 物化：`ffmpeg -f concat -c copy` 转封装成一个文件存盘。
2. 字节段表拼接：`Content-Length` 取各集之和，按 Range 把多个源拼成一条流。
3. 虚拟 HLS：把每集切成分片，自造 playlist，按分片回源。

## 决定

采用 **3**。

## 理由

- 方案 2 不成立：首集的 `moov` 声明时长只有第一集，拼字节后 Emby 时长条错、跳转到第二集读到 `ftyp` 垃圾。
- 方案 1 可行但违背「虚拟」目标：磁盘要额外存一份完整数据（1 万集约 500 GB），且合并规则一改就要重转。
- 方案 3 把时间轴交给 playlist、跳转交给分片序号：seek 是 O(1)，缓存天然按分片（LRU 粒度小），合并规则改动只重算 segment 表。

## 后果

- 每个分片一次 ffmpeg 冷启动（copy 模式 300–600 ms）；首次播放靠预取 2 片掩盖。
- 不能用「整集签名 URL」做鉴权，必须分片级 token。
- 分片切点依赖关键帧索引，索引缺失时该集降级为 `503 + Retry-After`，不出半截流。
- 单集（不合并）不走这条路，仍是 MP4 字节透传。
