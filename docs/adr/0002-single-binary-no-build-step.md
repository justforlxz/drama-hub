# ADR-0002：单二进制 + 无前端构建步骤

状态：已接受（2026-10-27）；**存储部分已被 ADR-0009 取代**（2026-10-31）
取代范围：原文「内嵌数据库作唯一存储」——2.0 起存储是必选外部依赖 PostgreSQL。
仍然有效：一个 Go 二进制装三个面、没有前端构建步骤。

## 背景

需要三个面：虚拟 WebDAV、出流服务、管理界面。部署环境是本机或一台小机器，使用者是个人（lxz）。
管理界面只有三页：剧目列表、合并编排、同步与缓存看板。

## 决定

- 一个 Go 二进制，包含全部三个面；**存储由 ADR-0009 决定**（PostgreSQL 为必选外部依赖，
  不再内嵌数据库）。
- 管理界面用 `html/template` + 原生 JS，资源 `embed` 进二进制。**没有 node、没有 npm、没有打包步骤。**
- 依赖只有标准库 + `x/net/webdav` + 数据库驱动（ADR-0009）。

## 理由

- 三页管理界面不需要框架和构建链；引入 Node 会让「起一个服务」变成「装两套工具链」，也让 CI 与新人上手成本翻倍。
- 单二进制让升级 = 替换文件 + 重启，回滚 = 换回旧文件（DB 迁移只向前，回滚需备份，见运维说明）。
  这条在存储外置后依然成立：二进制还是单文件，数据库是独立的部署项，不参与「替换文件」。

## 后果

- 复杂交互（拖拽排序等）用原生 JS 手写，代码量比框架方案大，但可控、无升级风险。
- 需要 SSE 或轮询做同步进度，不引入 WebSocket 库（标准库 `net/http` 的 flusher 足够）。
- 将来若界面需求膨胀，先写 ADR 再引入构建步骤，不允许悄悄加 `package.json`。
- 「跑起来」多了一个前置条件：有可连的 PostgreSQL（ADR-0009 的代价，已接受）。
