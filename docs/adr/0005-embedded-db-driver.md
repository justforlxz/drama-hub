# ADR-0005：内嵌数据库驱动选型

状态：**已被 ADR-0009 取代**（2026-10-31）
取代原因：存储后端整体换成 PostgreSQL，这个 ADR 选的不再是体系的一部分。
保留此文件只为记录「当时为什么必须引入第一个第三方依赖」这条判断。

## 背景（历史）

`database/sql` 是接口层，本身不含任何驱动。F2 的 settings 读写要落到内嵌数据库
（ADR-0002 当时的硬约束 4），因此必须引入第一个第三方依赖。

当时列出的候选与结论：

1. 事实标准的 cgo 驱动：被否决——它把 `CGO_ENABLED=0` 的交叉编译打掉。
2. 纯 Go 转译的内嵌数据库驱动：**采用**——纯 Go，不需要 cgo。
3. 自己写 SQL 文件格式解析 / 用 `os/exec` 调命令行：不成立。

## 决定（历史）

采用 2：纯 Go、无 cgo 的内嵌数据库驱动。

## 后果（历史）

- 第一个第三方依赖有了正当理由（标准库没有数据库驱动），「先写 ADR 再加依赖」这条
  流程从此有了实例。
- 具体驱动名与版本随 ADR-0009 一起从仓库消失：现在的驱动是 `github.com/jackc/pgx/v5`
  的 `stdlib` 适配层，见 ADR-0009。
