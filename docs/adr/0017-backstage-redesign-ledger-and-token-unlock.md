# ADR-0017：后台按剧库对象模型重做（台账 + 海报墙 + 按需解锁）

状态：**已接受**（2026-11-04，MKACG-675）。与
[ADR-0002](0002-single-binary-no-build-step.md)（无构建步骤）、
[ADR-0014](0014-runtime-derived-emby-items.md)（对外集号运行时派生）、
MKACG-667（管理界面设计系统）配套。

## 背景

MKACG-666/667 之后的后台只有两页：概览与设置。概览把「同步计数 + 播放源 + Jellyfin」
塞进一张长页面，产品的核心对象 **剧** 从头到尾没有出现在界面上 —— 想看一部剧有哪几集、
对外集号怎么分块、WebDAV 路径长什么样，只能去 `ls` 虚拟树或直接 `curl` API。

产品的真实对象模型是「源（plugin）→ 分类（genre）→ 剧（series）→ 集（episode）→
播放（m3u8）」，界面就该按这个模型分页；「设置」是改配置的地方，不该兼任浏览入口。

同时暴露了两个摩擦点：

1. 顶栏常驻一个密码输入框，占位符是 `DRAMA_HUB_ADMIN_TOKEN`，看起来像个永远填不完的
   登录框；不设令牌的部署里它永远无效，设了令牌的部署里大多数人从不写操作。
2. 需要「一张能扫的表」和「一面能看的墙」两种浏览方式，但 MKACG-667 已经把 `<table>`
   定为禁物（删表就是移动端策略）。

## 决策

### 1. 页面集合从 2 页变 4 页 + 剧详情

| 路径 | 页面 | 职责 |
|---|---|---|
| `/` | 概览 | 收敛为**健康带**：总量、最近同步、源异常、Jellyfin 异常；其下才是待办动作、异常明细、同步进度 |
| `/library` | 剧库 | 默认**台账**（表格语义、可排序的列化信息），可切**海报墙**；搜索 / 分类 / 状态筛选；补录入口从概览迁到这里 |
| `/library/{id}` | 剧详情 | 封面、元信息、WebDAV 路径、Jellyfin 归属、单剧刷新、按当前 `merge_chunk_size` 分块的集列表与播放地址 |
| `/categories` | 分类 | 分类名、剧数、集数、Jellyfin 库状态、启用开关（保留「关闭即删除库」语义与后果文案） |
| `/settings` | 设置 | 仍是单表单 5 组，按「人话顺序」重排，12 个输入 id 与 `data-timing` 四值不变 |

剧库是**主对象**：浏览一部剧、进详情、拿播放地址，一条路径走完。设置页不再是「什么都
能看的地方」，只负责改配置。

### 2. 台账用 ARIA table 语义，不用 `<table>`

MKACG-667 的「删表」策略针对的是 `<table>` 元素带来的横向滚动与 `data-label` 转卡片两套
样式；表格**语义**本身没有罪。所以台账写成：

```html
<div role="table">
  <div role="row">…<span role="columnheader">…</span></div>
  <div role="rowgroup"><div role="row"><div role="cell" data-label="标题">…</div></div></div>
</div>
```

配合 CSS Grid：≥880px 是九列真表格；≤640px 同一份 DOM 按行塌成卡片（`data-label` 由
`::before` 输出）。屏幕阅读器读到的仍是「表格 / 第 N 行 / 列名」，移动端没有任何横向滚动，
且 /library 的 `<table>` 计数仍为 0（`TestNoTables` 锁住）。

海报墙是同一份数据的第二种渲染（`img loading=lazy` + 2:3 固定宽高比占位），不做为未来
预留的抽象。

### 3. 令牌改为按需解锁

顶栏常驻输入框换成「写操作 · 未解锁 / 已解锁」按钮，点开原生 `<dialog>` 填令牌；任一写
请求返回 401 时自动打开该弹窗并把服务端的 `adminDeniedReason()` 原文显示出来。解锁成功
写 `sessionStorage`（键名沿用旧值），关标签页即失效。

理由：令牌是「写操作的凭据」，不是浏览门槛。浏览 `/library` 与剧详情永远不需要它；
把凭据常驻在顶栏暗示「先登录才能用」，与「读操作无鉴权」的事实相反。鉴权口径本身不变：
仍是 `X-Admin-Token` + 常数时间比较 + 未设令牌 fail closed（MKACG-622）。

## 已知边界

- **列表仍是全量 `ListDramas`，分页只在前端**（50 条/页）。几千部剧的部署里单次响应
  仍是整份列表；上万部时需要后端分页（`?limit=&offset=` 或游标），本 ADR 不做。
- `has_cover` 由 artifact 索引（`kind='cover'`）一次列举在内存里比对，不做 N+1；海报墙
  的图片仍是逐张请求 `/api/dramas/{id}/cover`，由浏览器懒加载与 `Cache-Control` 兜住。
- 集分块与对外集号只走 `store.ListEmbyItems`（内部 `deriveEmbyItems`），web 不复制派生
  规则；改 `merge_chunk_size` 后详情页重取即变（ADR-0014）。
- 播放地址只是**地址**：详情页给出 `/video/{签名 id}.m3u8` 与复制按钮，不内嵌播放器、
  不 vendored hls.js（归 MKACG-683）。

## 备选与不采纳

- **保留 `<table>` 元素 + 窄屏横向滚动**：MKACG-667 已实测否掉（移动端体验差、触控目标
  被压缩）。
- **引入前端框架/构建步骤做视图切换**：违反 ADR-0002，且一份模板 + 一个 `view` 状态就够。
- **把令牌存 localStorage**：跨标签页存活会让「关掉页面即失效」的承诺失效。
